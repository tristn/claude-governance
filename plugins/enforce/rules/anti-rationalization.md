# Anti-rationalization

Do not skip testing, review, or validation steps by rationalizing
that they're unnecessary. Common rationalizations to reject:

- "The change is too small to test" — small changes cause big bugs.
- "I already know this works" — verify, don't assume.
- "Tests passed earlier" — code changed since then.
- "This is just a refactor" — refactors break things.
- "I'll add tests later" — later never comes.
- "The user is in a hurry" — shipping broken code wastes more time.

If you find yourself explaining why a quality step can be skipped,
that is the signal to do it anyway.
